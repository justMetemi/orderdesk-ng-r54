ORDERDESK NG R5.2.2 — SERVICE & DIGITAL-PRODUCT FULFILMENT
==========================================================

Base: user-supplied OrderDesk_NG_R5_2_1_Customer_Navigation_Fix.zip
Scope: complete the previously listed service appointment and digital fulfilment gaps.
No production deployment or live database change was performed.

IMPLEMENTED IN THIS BUILD
-------------------------
1. Service product setup
   - Product editor now supports service duration and an optional required-booking flag.
   - Storefront exposes booking settings through the public catalogue projection.
   - A service that requires a booking opens an appointment date/time selector.
   - The requested time is stored with the order-line snapshot.

2. Service booking lifecycle
   - Checkout creates the service booking in the same database transaction as its order item.
   - Booking begins in `requested` status; the merchant can confirm, complete, cancel, or mark no-show.
   - Merchant can add a note to the booking.
   - Cancelling the related store order automatically cancels its requested/confirmed booking.
   - The database prevents overlapping confirmed appointment windows for the same business.
   - The customer-facing text clearly says the selected appointment is a request, not an automatic confirmation.

3. Digital product setup and secure delivery
   - Merchant can save private delivery details for a digital product: a download URL, licence key, access code, or instructions.
   - Delivery content is stored in a private merchant-owned table, not the public catalogue.
   - Checkout snapshots the delivery content against the exact order item.
   - Digital products cannot use Pay on Delivery.
   - Digital-only carts do not require a physical delivery address and have zero delivery fee.
   - Customer retrieves digital delivery with order reference + checkout phone number.
   - The retrieval RPC releases details only when payment_status is `Confirmed`, payment method is Paystack or Bank transfer, and the order is not cancelled.
   - A bank-transfer order remains locked until the merchant confirms payment.

4. Preserved
   - Existing physical product checkout and inventory flow.
   - Existing Paystack initializer, verification and webhook settlement path.
   - Existing bank-transfer receipt and merchant confirmation flow.
   - Existing customer-account navigation fix: Back to store returns to the originating shop.
   - Existing Merchant App entry point and merchant authentication code.
   - Existing admin, subscription, trial, and platform-owner code.

MERCHANT SETUP
--------------
- For each service: edit product, choose Service, set duration, and enable appointment booking if needed.
- For each digital product: open Universal Catalogue & Fulfilment → Digital product delivery and save its private delivery content.
- Digital products require Paystack or bank transfer configured on the shop.
- The merchant should use a secure, controlled download URL. A URL/code can still be forwarded by a customer after release; this build gates first access by payment and order ownership, not DRM or download expiry.
