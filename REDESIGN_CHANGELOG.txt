Safe test order
1. Create a separate Supabase TEST project. Do not use production.
2. Run schema.sql, then schema2.sql, then the existing subscription/payment setup required by your source, then online_store_upgrade.sql.
3. Use the test project's URL and public anon/publishable key in index.html and shop.html. Never use a service-role key in browser code.
4. Configure Google OAuth only if testing Google sign-in.
5. Serve the folder locally using a static HTTP server. Test registration, sign-in, manual orders, product stock, reports, subscription screens, AI function separately, store setup, publish/hide, bank transfer receipt, pay on delivery, order tracking, cancellation/restock, duplicate checkout and cross-business isolation.
6. Only after all tests pass should you decide whether to deploy. No deployment is included in this package.
